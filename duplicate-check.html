What this returns, and what it does not

Worth stating plainly, because the boundary is the point.

Returned

  • ✓Yes or no — has this number sold as Priority or Hot in the last 365 days
  • ✓At most, the month it last sold

Never returned

  • ✕Buyer name, sale price, or lead ID
  • ✕Consumer name, address, or any other field
  • ✕Which affiliate originally sent the lead
  • ✕Anything at all for a number that has not sold
Build note. This is a suppression-list API in disguise, so the containment has to be in the design, not the UI: return a boolean, rate-limit per partner per day, log every query with the partner ID, and reject bulk jobs above the cap rather than truncating them silently. A partner who can query without limit can enumerate the database one number at a time.
